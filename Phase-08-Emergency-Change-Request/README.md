# Phase 8 — Emergency Change Request

## 📌 Overview

This phase demonstrates the integration between Incident Management and Change Management.

During the Level 2 investigation in Phase 7, the Network Support team identified a VPN gateway configuration issue that required a network-level configuration change.

Because the Incident requires an urgent corrective action, an Emergency Change Request is created in ServiceNow.

The Change Request provides a controlled and traceable method for documenting, assigning, implementing, and tracking the required configuration change.

---

## 🎯 Objective

The objectives of this phase are:

- Create a Change Request from the identified Incident requirement.
- Classify the Change as an Emergency Change.
- Document the reason for the Change.
- Assign the Change to the appropriate support group.
- Assign the responsible technical resource.
- Establish a relationship between the Incident and Change.
- Prepare the Change for implementation.

---

# 🧑‍💻 Business Scenario

The original Incident involves a corporate VPN connectivity problem.

The Level 2 Network Support investigation identified a VPN gateway configuration issue.

The existing configuration must therefore be modified to restore VPN connectivity.

Because the corrective action needs to be handled urgently, an Emergency Change Request is created.

---
