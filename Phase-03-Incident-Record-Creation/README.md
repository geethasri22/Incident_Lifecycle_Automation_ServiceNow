# Phase 3 — Incident Record Creation

## 📌 Overview

This phase focuses on creating the primary Incident record in ServiceNow for the corporate VPN connectivity problem.

The Incident record is the central object used throughout the project. It is progressively classified, prioritized, assigned, investigated, escalated, associated with Knowledge and Change records, and finally resolved.

The incident created during this phase provides the foundation for the remaining Incident Lifecycle Automation workflow.

---

## 🎯 Objective

The objectives of this phase are:

- Create a new Incident record.
- Capture the reported user issue.
- Associate the Incident with the configured Service.
- Associate the Incident with the appropriate Service Offering.
- Provide a meaningful Short Description.
- Document the issue using the Description field.
- Establish the initial Incident state.
- Generate and verify the Incident number.

---

# 🧑‍💻 Business Scenario

The project uses a corporate VPN connectivity problem as the primary incident scenario.

### Reported Issue

> An employee is unable to connect to the corporate VPN.

The incident is initially reported to the IT support team for investigation.

The Incident is created in ServiceNow so that the issue can be tracked throughout its complete lifecycle.
